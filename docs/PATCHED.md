# Patched bindings

The bindings are generated by [runic](https://github.com/Samudevv/runic) from the C headers.
Two things change the generated output: rules that `make generate` applies every time, and
hand-written code. Regenerating applies the rules again and leaves the hand-written files
alone; a typed pin in the package's `patched.odin` makes a regeneration that drops a hand fix
fail to compile.

To regenerate, run `make generate` and then `make ci`.

## Generation rules

`scripts/postprocess.sh <pkg>` applies these to `<pkg>/<pkg>.odin`, in this order. They are
odin-gtk's rules, trimmed to what runic 0.8 produces from the system headers.

| package | rule | reason |
|---|---|---|
| `glib` | `^char` becomes `cstring`; parameters named `data`, `buf`, `buffer` go back to `^byte`, `inbuf` and `outbuf` to `^^byte` | `gchar *` is a typedef'd char pointer, which runic leaves as `^char` |
| `glib` | `MININT`, `MAXINT`, `MAXSIZE` and the other limit macros become `min(T)` / `max(T)` | the macros are casts and shifts runic emits as strings |
| `glib` | backticks and backslashes dropped from `MINOFFSET`, `MAXOFFSET`, `TIME_SPAN_*`, `LOG_*`, `VARIANT_TYPE_*`, `URI_*`, `NSEC_PER_SEC`; the `L` and `U` integer suffixes dropped from the values only | macro text runic quotes as a string |
| `glib` | `FALSE`, `TRUE` become `false`, `true`; `SOURCE_REMOVE`, `SOURCE_CONTINUE` become `FALSE`, `TRUE` | a `SourceFunc` returns `boolean`, which an untyped integer constant does not convert to |
| `glib` | `*_ERROR` quoted calls (`THREAD_ERROR`, `FILE_ERROR`, …) become the quark procedure (`thread_error_quark`) | macro text runic quotes as a string |
| `glib` | `HOOK_FLAG_USER_SHIFT` loses its backticks; `LOG_DOMAIN` is dropped | the first is an integer; the second is `((gchar*) 0)`, which no Odin constant can be |
| `glib` | `LOG_FATAL_MASK` is `LogLevelFlags{.LOG_FLAG_RECURSION, .LOG_LEVEL_ERROR}` | the C expression ORs enum members |
| `glib` | `[^]` for a `data` field that is a pointer | a pointer to an array of elements |
| `gobject` | `^glib.char` becomes `cstring` | as above |
| `gobject` | `TYPE_*`, `SIGNAL_*`, `VALUE_*` macros lose backticks and the `(GType)` cast; `TYPE_PARAM_*` become procedures returning `param_spec_types[n]` | macro text runic quotes as a string |
| `gobject` | `PARAM_STATIC_STRINGS` is `ParamFlags{.STATIC_NAME, .STATIC_NICK, .STATIC_BLURB}`, `class: [^]` becomes `class: ^` | the C expression ORs enum members; a pointer to one class struct |
| `gio` | `^glib.char` becomes `cstring`; the strings `TRUE` and `FALSE` become `glib.TRUE` and `glib.FALSE` | as above |
| `gio` | backticks, backslashes and `g_…()` calls dropped from `FILE_ATTRIBUTE_*`, `*_ERROR`, `TYPE_*` and the other string macros, so `TYPE_FOO` names `foo_get_type` | macro text runic quotes as a string |
| `glib`, `gobject`, `gio` | the flag enums listed in [DECISIONS.md](DECISIONS.md) §8 become `bit_set`s (below) | callers write `{.A, .B}`; the type keeps the C size and bits |
| all | `to.detect.parameters: declared` in each `rune.yml` types every procedure parameter `^T` (`T **` is `^^T`) unless `arrays:` lists it; `param_rules` in `postprocess.sh` puts right what `declared` does not cover: struct members and variables whose name ends in "s" (`^T` where the header declares one `T *`), the real arrays among callback-type parameters (`[^]T`), and the `gchar ***` procedure parameters (`^[^]cstring`); a `const gchar *` buffer with a length is `^byte` | runic writes `[^]T` for a pointer whose name ends in "s" (`settings`, `res`, `address`, `bytes`, `credentials`, `subprocess`, `vfs`, `parameters`), however many elements it holds, and `[^]T` can be indexed past one. Real arrays (`args`, `entries`, `vectors`, `param_values`, `param_types`, `names`, `values`, `strings`, `dirs`, ...) have a length or a NULL terminator and stay `[^]` |
| `glib`, `gobject`, `gio` | the 22 procedures whose last C parameter is a `va_list` are skipped by runic, each leaving a comment in the output (DECISIONS §11) | runic 0.8 drops the `va_list` and writes `#c_vararg ..any`: a wrong call; the fork skips them |
| all | `Foo :: _GFoo` is deleted and `_GFoo` becomes `Foo` | one name per struct |

### Flag sets

`bit_sets` in `postprocess.sh` rewrites, for each enum on the package's list,

```
SpawnFlags :: enum u32 {SPAWN_DEFAULT = 0, SPAWN_SEARCH_PATH = 4, …}
```

into `SpawnFlagsBit :: enum u32 {SPAWN_SEARCH_PATH = 2, …}` (bit indices),
`SpawnFlags :: bit_set[SpawnFlagsBit; u32]` and `SPAWN_DEFAULT :: SpawnFlags{}`. Composite
members become constant sets, or a `transmute` of the C value when they carry a bit with no
member. The rules for names are DECISIONS §8. Each package's `patched.odin` asserts the size of
the flag types that cross the C boundary by value, so a regeneration that changes it fails to
compile.

`scripts/type-casts.sh` writes `gio/type_casts.odin`: `FOO` and `IS_FOO` for every
`TYPE_FOO :: foo_get_type` in `gio.odin` that has no error quark, and `gobject/type_casts.odin` for the listed GObject classes
(DECISIONS §12).

## `gobject`

`signal_handlers_disconnect_by_func`, `signal_handlers_disconnect_by_data`,
`signal_handlers_block_by_func` and `signal_handlers_unblock_by_func` are the C macros of the
same names, written in `gobject/helpers.odin` over the `_matched` procedures. A regeneration
does not touch them; `test_signal_handler_macros` (`gobject/gobject_test.odin`) pins their
behaviour.

## `gio`

`g_application_run` is ignored by generation (`rune.yml`, `ignore.functions`) and declared in
the hand-written `gio/wrapper.odin`, together with `application_run`. The pin is
`patched_application_run` in `gio/patched.odin`.

`application_run` builds a C `argv` from `args`: one `GString` per argument, collected in a
`GPtrArray`. Keeping only each `GString`'s `str` and freeing that leaks the 24-byte `GString`
struct for every argument, and `ptr_array_free(argv, false)` leaks the array's segment as
well. Each buffer is taken with `string_free(g_str, false)`, which frees the struct and hands
the characters over, and the array is freed with its segment.

| proc | signature | change |
|---|---|---|
| `application_run` | `(application: ^Application, args := os.args) -> i32` | `ptr_array_add(argv, string_free(g_str, false))`; `ptr_array_free(argv, true)` |

`test_application_run_leaves_no_argv_behind` (`gio/gio_test.odin`) pins the patch: it runs the application over 4000
arguments and fails if the heap (glibc `mallinfo2`) grows by 16 KB or more across a run, which the leaking form exceeds
by a factor of ten. It needs `ODIN_TEST_THREADS=1`, which the Makefile sets. Under `ASAN=1` malloc is replaced and the
measure reads zero, so AddressSanitizer's own leak report is the check there.

## Pointer parameters, audited

`scripts/check-generated.sh` (`make check-generated`, run by `make lint`) lists every corrected
`declaration, parameter` and fails when one is `[^]T` again, and fails when a `va_list`
procedure is bound. The pins are in each package's `patched.odin`: one per distinct parameter
name and type, named after the procedure (`patched_settings_list_children` in `gio`), plus `AsyncReadyCallback` and the struct fields
`Completion.items`, `InputMessage.address` and `InputMessage.control_messages`.

The audit read the C header for each of the 397 procedure parameters (and the callback and
struct-field uses of the same names). Corrected: `res`, `settings`, `subprocess`, `vfs`,
`credentials`, `address`, `bytes`, `parameters` (`GVariant *`), `items`, `files`, `uris`,
`targets` (`GList *`), `lhs`, `rhs`, `klass`, `tuples`, `status`, `flags` and the scalar
out-parameters `n_ids`, `n_values`, `num_files`, `start_pos`, ... Left as arrays, each with a
length or a NULL terminator in the header: `args`, `dirs`, `names`, `groups`, `protocols`,
`entries`, `fields` (`GLogField`), `vectors`, `messages`, `fds`, `keys`, `values`,
`param_values`, `param_types`, `parameters` (`GParameter`), `pspecs`, `const_values`,
`attribute_names`, `bytes` (`guint8 *`) and the DBus info arrays.
